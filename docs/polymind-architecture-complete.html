Zustand Store Architecture

Polymind uses 5 independent Zustand stores with localStorage persistence via middleware.

Store Key Purpose
userStore gyanmarg-user Profile, onboarding status, settings, favoriteModules, pendingAchievement
progressStore gyanmarg-progress XP, level, completedLessons, achievements, streaks, bookmarks, starred cards, challenges, pendingLevelUp
spacedRepetitionStore gyanmarg-spaced-repetition SM-2 algorithm data: unlockedCards, reviewHistory, easeFactor, intervals
gameStore gyanmarg-games Post-lesson mini-game scores, totalGamesPlayed, totalGameXP
firebaseSync (no storage) Sync trigger stub for future Firebase integration

Persistence Strategy

🔄 Save Flow
  1. User action triggers store update
  2. Zustand middleware intercepts state change
  3. State serialized to JSON
  4. Saved to localStorage with key prefix
  5. Firebase sync stub called (no-op currently)
📥 Load Flow
  1. App initializes
  2. Each store checks localStorage for saved state
  3. If found, deserialize and hydrate store
  4. If not found, use default initial state

Spaced Repetition System

Page 9

SM-2 Algorithm Implementation

Polymind uses the SM-2 (SuperMemo 2) spaced repetition algorithm to optimize review timing.

interface CardState { cardId: string; easeFactor: number; // 1.3 to 2.5 (default 2.5) interval: number; // Days until next review repetitions: number; // Times reviewed correctly nextReview: Date; lastReviewed: Date; } function calculateNextReview( quality: number, // 0-5 (0=complete blackout, 5=perfect) card: CardState ): CardState { let { easeFactor, interval, repetitions } = card; // Update ease factor easeFactor = Math.max(1.3, easeFactor + (0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02))); // Update interval if (quality < 3) { // Failed: reset repetitions = 0; interval = 1; } else { // Passed: increase interval repetitions++; if (repetitions === 1) { interval = 1; } else if (repetitions === 2) { interval = 6; } else { interval = Math.round(interval * easeFactor); } } return { ...card, easeFactor, interval, repetitions, nextReview: addDays(new Date(), interval), lastReviewed: new Date() }; }

Adding a New Module

Page 14

Step-by-Step Checklist

✅ Step 1: Create Lesson Content

File: src/data/pathways/{module-id}-lessons.ts

  • Export named arrays: {prefix}LessonsLevel1, {prefix}LessonsLevel2, etc.
  • Each level: ~8 lessons (intro, concepts, quiz, exercise, reflection)
  • Lesson IDs: {prefix}-001, {prefix}-002, etc.
  • Properly escape single quotes in content
✅ Step 2: Create Pathway Structure

File: src/data/pathways/{module-id}.ts

  • Import lesson arrays from step 1
  • Create PathwayLevel[] array
  • Level IDs: {prefix}-level1, {prefix}-level2, etc.
  • Set XP unlock requirements: 0, 500, 1000, 1500...
  • Export as default
✅ Step 3: Update Pathways Index

File: src/data/pathways/index.ts

  • Add export: export { default as {moduleName}Pathway } from './{module-id}';
✅ Step 4: Update Module Config

File: src/data/modules.ts

  • Import pathway: import { {moduleName}Pathway } from './pathways/{module-id}';
  • Find module entry with matching ID
  • Set isAvailable: true
  • Add pathway: {moduleName}Pathway
✅ Step 5: Create Images

Directory: src/assets/ai-images/

  • Module image: modules/module-{module-id}.webp
  • Level images: levels/level-{prefix}-1.webp, level-{prefix}-2.webp, etc.
  • Use AI generation script or design manually
✅ Step 6: Register Images

File: src/lib/moduleImages.ts

  • Import module image: import {moduleName}Img from '@/assets/ai-images/modules/module-{id}.webp';
  • Import level images: import {prefix}Level1 from '@/assets/ai-images/levels/level-{prefix}-1.webp';
  • Add to moduleImages record
  • Add all levels to levelImages record

✓ Module Should Now...
  1. Appear in Module Hub (not grayed out)
  2. Show correct image
  3. Open to level list when clicked
  4. Show lessons when level expanded
  5. Open lesson viewer when lesson clicked
  6. Show level images in lesson viewer
  7. Track completion in progress store
